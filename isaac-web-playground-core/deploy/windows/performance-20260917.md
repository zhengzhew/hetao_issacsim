# 本机画质与性能测试：2026-09-17

结论：本机可以提供明显高于最初低清配置的画面。已采用当前 MJPEG 服务支持的最高分辨率档：请求 1920×1080、实际 1920×1072、JPEG 质量 90、目标上限 30 FPS。仓库场景持续接收实测约 24.5 FPS；这不是所有场景或长期运行的性能保证。

## 环境与方法

- Windows 本机同时运行 Node.js、Isaac Sim 6.0.1 和网页客户端；RTX 5060 Laptop，8151 MiB 显存。
- 真实仿真 `mock=false`，warehouse 场景、NVIDIA Jetbot。Kit 隐藏视口 640×352，独立 Replicator 图像按各档分辨率重新渲染，并非低清图片放大。
- 每档预热约 6 秒、采样约 30 秒；采样时有 2 个 MJPEG 连接。FPS 按服务端实际生成帧计数计算，温度与显存约每 2 秒采样。
- 测试过程中修正了串流循环只在启动时读取帧率的问题，并将原先 40ms 间隔下限改为最高 30 FPS。表格只包含修正后的仓库测试。
- 回退监测线设为 GPU 温度 85°C、显存使用 90%，并检查桥接/采集错误。它们是此次保守测试的停止条件，不是硬件厂商极限。不调整频率、功耗、驱动或系统安全设置。

## 高清持续串流与控制

选用 1920×1072、质量 90、目标 30 FPS，持续测试 120.06 秒。新增一个本机 HTTP 接收客户端解析完整 MJPEG 帧，同时每约 100ms 提交虚拟机器人控制：每 30 秒内先原地转动 15 秒、再停止 15 秒。测试结束发送停止命令。

- 接收端实测：24.52 FPS，无串流读取错误。
- 接收图像数据：约 49.52 Mbps／客户端，不含协议开销；不是局域网带宽测试。
- 帧间隔 P95：63ms，最长间隔 203ms。
- 786 次控制请求，响应耗时 P95 63ms、最大 188ms。此项仅是 HTTP 命令往返，不代表按键到屏幕变化的完整延迟。
- GPU 最高 79°C，平均利用率约 57.6%，最高显存 3152 MiB；未触发此次温度、显存停止条件。

两分钟测试支持将此档作为当前演示设置，但不能证明数小时热稳定性、多会话并发能力或全部复杂场景表现。多个观看端共享同一个仿真；网络发送流量会随观看端增多。

## 使用与边界

启动脚本已默认采用上述高清档。720p/30 FPS/质量 85 是降低网络流量和渲染负载的备用档，切换命令见 [Windows 部署说明](README-native.md)。运行时帧率设置现会作用于已连接的串流。

已直接检查输出图像，确认机器人和地面细节正常。此次浏览器自动化连接失败，未将 HTTP 接收验证冒充浏览器渲染验证；另一台局域网设备的显示与控制体验仍需单独确认。房间场景曾出现镜头被遮挡的灰色画面，其早期试测已从表格排除。

本地原始数据与图像位于忽略提交的 `run/quality-ladder.json`、`run/quality-results.json`、`run/quality-soak.json`、`run/quality-*.jpg`；测试脚本为 `run/quality-benchmark.py` 和 `run/stream-soak.py`。
