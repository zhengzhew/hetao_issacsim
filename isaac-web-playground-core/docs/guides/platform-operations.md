# 体验台运行与设备配对

## 本地使用

1. 在服务器双击仓库根目录的 `启动服务.bat`。当前服务器浏览器使用 `http://localhost:8080/`，局域网设备使用启动脚本显示的地址。IP 可能随网络变化。
2. 首次老师密码打开 `run/platform/teacher-password.txt` 查看；在 `/manage` 登录。密码和 `access.json` 都保留在服务器，不能随连接器分发。
3. 选择体验台。若当前电脑就是体验浏览器，点击“在此电脑打开体验”；另一台体验电脑使用一次性的“浏览器配对码”进入。原生视频实例只供一个浏览器观看，老师管理页不占视频连接。
4. 在接着机械臂 USB 的 Windows 电脑下载 `/downloads/so101-leader-windows.zip`，完整解压，停止旧连接器，再运行新版 `SO101-Leader.exe`。
5. V6 主界面填写服务器地址，例如公司部署的 `https://10.72.255.16`。到教师端选择同一个体验台，生成“采集器配对码”，填入主界面的固定输入框。点击“添加配置”，选择该臂的 .robot.json 配置包或主臂校准 JSON，再点“连接机械臂”。每台臂添加一次，换臂先停止，再从配置列表选择。单个 USB 串口自动选择；多个设备时展开“连接设置”选择。服务器、串口和校准会记住，V6 统一使用配对码，不走局域网免配对。
6. 在体验浏览器选机械臂关卡，再开始同步。换关卡后自动重新接管；采集器仅读取实物关节，不给实物舵机发送位置控制。
7. 结束时先停止连接器，再双击服务器的 `关闭服务.bat`。关闭网页不会关闭 GPU 仿真。

启动脚本优先使用 `%LOCALAPPDATA%/Programs/nodejs/node.exe`，与本机已放行程序一致；也可用 `-NodePath` 指定。网页服务和防火墙规则必须对应同一个 Node 可执行文件，不能只检查端口号。

浏览器及采集器配对码有效 5 分钟、仅使用一次。连接凭证有效 12 小时；V6 会记住有效采集器凭证，过期后由老师生成新采集器配对码。配对码输入框始终显示，不需展开设置。浏览器单独配对；换浏览器时由老师解除旧配对并生成新码。凭证保存在采集电脑 `%LOCALAPPDATA%/HetaoIsaacConnector`，不随压缩包分发。

## 配置记忆与设备识别

连接器把设置和校准文件副本保存在采集电脑 %LOCALAPPDATA%/HetaoIsaacConnector，重新解压升级程序或移动原始校准文件后仍能恢复。日志也保存在该目录下 logs。凭证独立保存，压缩包不包含密码、凭证或个人校准文件。

GUI 根据校准文件与显式 USB 绑定生成稳定编号，使用构建包指定的德晟 SE 或飞特 STS3215 驱动；文件格式和 USB 芯片不能推断舵机协议。飞特包核对六个舵机型号后开始采集。已有 USB 序列号时，即使 COM 号变化也按原设备恢复，不打开未知串口试探协议。构建和升级见 [飞特连接工具说明](feetech-connector.md)。

命令行仍支持显式 --arm-id：服务器记录编号、驱动与校准 SHA-256，同一显式编号换校准文件时由老师确认。简化 GUI 更换文件会生成新配置编号，省去手填编号与绑定变更确认，但仍需选择该实物臂对应的文件。

## 多门店配置

`configs/platform.json` 每个 station 启动独立 Node 与 Kit 进程，分配独立端口、GPU、上传目录、场景与关卡状态。浏览器和采集器配对到同一个 station，不能通过请求参数切换到其他 station。

默认仅一个实例。第二个实例必须配置不同的 `id/webPort/bridgePort/signalPort/mediaPort`。增加实例不会自动添加防火墙规则；单台显卡也不保证能跑两个实例。多服务器路由、GPU 容量规划、异地网络、无人值守部署和 8 小时稳定性仍需专门验收，不能把本机通过当作上云就绪。

当前入口 HTTP 面向受信局域网。公网前需 HTTPS/WSS，配置 `publicOrigin` 和 `secureCookies:true`；NVIDIA 原生视频端口需要私网/VPN或其他网络访问控制。8081 等内部 Node 端口及 8765 桥接端口不要公开。老师登录保护的是网页/API，并未给原生视频端口增加同等认证。

## 延迟与诊断

串口独立采样，网络发送取最新值，等待确认不阻塞 USB 读取。WebSocket 保持连接，待发送位置只保留最新一份。样本有效期默认 250 ms，TCP 重连、排队消耗这同一份有效期；已过期而尚未执行的样本被丢弃。正在 Kit 内执行的长操作无法中途取消。断流约 0.5 秒保持姿态，5 秒释放接管。

管理页按体验台显示设备、跟随采样、控制确认耗时和各浏览器视频上报，超过 15 秒的报告显示过期，另记录实际视频呈现情况。这里的确认耗时不等于手到画面的总延迟；现场需同时拍摄实物动作与显示器画面测量。WebSocket 基于 TCP，公网丢包仍可能产生阻塞；先用现场指标验证，必要时再实现不可靠有序/无序 DataChannel 传输姿态，而不是把本机确认耗时当成 WAN 结论。

日志在 `run/platform`，每个实例有自己的 Node/Kit 日志，单文件 10 MiB 轮转，保留 3 个历史文件。进程失败退避重启最多 5 次；Kit 重启会重置关卡，不会恢复物体摆放。配置、配对数据和运行日志均与代码分开。

## 连接器简化（2026-10-16）

以下是旧版本验收记录。V6 已改为主界面配对码连接，当前操作以上方流程为准。

主界面显示配置列表、“添加配置”、连接/停止及状态；服务器、串口和配对码放在“连接设置”。每台臂选择自己的文件并添加一次，之后从列表切换。重新打开会恢复上次选择，不会从下载目录或项目目录猜测哪一份属于当前实物臂。

本轮配置存取与恢复测试 9 项、真实 Tk 控件流程测试 5 项通过；GUI 测试使用模拟 USB 枚举和工作进程，没有打开实体串口。根据用户明确授权，当前服务器启用本机及 WLAN 同一 IPv4 子网内的连接器免配对。浏览器登录、体验台分配与控制隔离保留。另一台电脑的实体同步需更新程序后现场确认。

免配对配置位于 configs/platform.json 的 localConnector：enabled 为 true，interfaces 显式列出 WLAN。服务器按真实连接地址和该网卡当前子网判断，不信任代理转发头；拒绝浏览器 Origin/Sec-Fetch 请求，配置 publicOrigin 时停用。设备凭证只绑定选中的体验台与连接地址，不授予老师或体验浏览器权限；已有连接器占用时拒绝接管。网络范围会在连接存续期间定时重检。

选择本机以外的服务器时，使用服务器当前 IP，不填采集电脑自己的 IP。下载包的默认地址由构建参数 --server 指定；换网络后在“连接设置”中改一次。不同网络或旧服务器仍可使用原有采集器配对方式。

本轮最终验证：CPU 测试 92 项、真实 Tk 控件流程 5 项通过；浏览器登录、配对、管理隔离及免配对说明通过。最终 EXE 启动和通过当前 WLAN 地址取得设备凭证通过（用不存在的 COM999 验证错误出口，未打开真实串口）。随后通过真实 8080 入口与当前 Isaac Sim 完成 6 关节握手，管理接口返回 403；未发送关节目标，结束后释放连接并注销测试凭证。下载 ZIP 完整性和服务端文件一致性通过。上述局域网地址验收从服务器自身发起，不代表另一台电脑的 USB、无线网络或实体跟随已经验收。

### 多机械臂配置切换（2026-10-16）

使用步骤：停止同步 → 在“当前机械臂配置”选择对应文件 → 连接机械臂。第一次使用某台臂时点“添加配置”。建议用“一号臂.json”“二号臂.json”等容易识别的文件名；不同内容的同名文件会按来源目录区分。添加和切换不要求新增配对验证。

各份配置独立保存原始文件名、文件副本和串口记录；旧版单文件设置会恢复成列表中的一项。原文件被修改时，已保存的配置继续使用原副本，需要主动“添加配置”才能载入修改后的内容。配置副本与原文件都找不到时提示重新添加，不会改用另一台臂的配置。USB 接口用于恢复串口，不能自动判断实物机械臂身份；换臂时由操作者选择。

本轮 14 项配置存取测试、7 项真实 Tk 控件流程测试、5 项接入兼容测试及 Python 语法检查通过。覆盖不同关节参数、同名文件、原文件移动、旧版迁移和切换后传给工作进程的文件；串口与工作进程使用测试替身，没有连接多台实体臂。浏览器登录、体验台隔离及服务端免配对规则保持当前实现。


### 门店 .robot.json 配置包（2026-10-16）

“添加配置”现在支持门店入口文件，例如“北京门店（喜隆多）.robot.json”。首次导入时保留整个门店文件夹及 calibration 子目录。连接器读取 calibration.leader_output 指向的主臂文件，显示 label，使用 expected_devices 中 runtime_role 为 leader 的 USB 序列号寻找串口；不会读取从臂校准，也不会运行配置包中的 program、arguments 或 tool。

兼容两种主臂校准：原有 lerobot_style_desheng_v401 格式，以及 shoulder_pan / shoulder_lift / elbow_flex / wrist_flex / wrist_roll / gripper 六关节格式。后者的 homing_offset 是 SO101-Calibrate 在导出前已写入舵机的偏移记录，采集时不再次叠加；每个关节使用自己的 range_min/range_max 与 drive_mode。此导入不重标定、不写舵机寄存器，也不自动修改六轴方向。

导入后缓存实际主臂校准，并保留入口名称和主臂 USB 绑定。以后移动原配置包或升级连接器仍能恢复。两个配置包即使校准数据相同，只要主臂 USB 绑定不同，也会分别保存。指定主臂未插入时不会自动选择唯一在线的从臂；配置包缺文件会提示具体路径。

这次验证覆盖配置导入、缓存恢复、同参数不同 USB、旧配置升级、六轴范围/偏移及真实 Tk 按钮流程。USB 枚举与工作进程采用测试替身；实物通信仍使用此前已验证的 SE 读取协议，未在北京门店主臂上验证方向、范围和连续同步。
